# แผนรอบ 17: บัญชีผู้ดูแล (ข้อมูลอยู่ในสถานะจบเกม เครดิตจำนวนมาก)

> **ปรับแผนระหว่างทำ:** ผู้ใช้สั่งว่าให้ทุกบัญชีมีโหมดเหมือนกัน แค่ให้บัญชีผู้ดูแลเป็นสถานะจบเกม จึงเลิกทำโหมดผู้ดูแลที่สลับได้ (ปุ่ม ป้าย ∞ และการไม่บันทึก) เปลี่ยนเป็นตั้งข้อมูลของบัญชีผู้ดูแลเป็นสถานะจบเกมจริงและบันทึกตามปกติ (ใต้ห้อง SOLO) ส่วนฐานข้อมูล (ตาราง admins, is_admin, บังคับห้อง SOLO) ตามแผนเดิม ดูผลที่ GDD ข้อ 30

สถานะ: **โค้ดและเทสต์เสร็จแล้ว รอผู้ใช้รันคำสั่ง SQL บนฐานข้อมูลจริง** (ผู้ใช้ยืนยันตามที่แนะนำทั้ง 3 ข้อ ผมรัน DDL เองไม่ได้เพราะ `.env` มีแค่คีย์ service role ซึ่งไม่ใช่สิทธิ์สร้างตาราง) (เขียนเมื่อ 30 ต.ค. 2569 จากโค้ดที่ commit `0fedd03`)

## สิ่งที่ผู้ใช้ขอ

- บัญชีที่เข้าสู่ระบบด้วย Google ของผู้ใช้ (thapananthongpak@gmail.com) เป็นบัญชีผู้ดูแล: เข้าเกมแล้วอยู่ในสถานะจบเกม (endgame) และมีเครดิตไม่จำกัด
- บัญชีอื่นทุกบัญชี (นักเรียน บัญชีไม่ระบุตัวตน บัญชี Google อื่น) ต้องไม่ได้สิทธิ์นี้ ไม่ใช่ว่าเด็กเข้ามาเล่นแล้วจบเกมเลย

## สภาพตอนนี้ (ตรวจโค้ดแล้ว)

- การเข้าสู่ระบบด้วย Google ทำผ่าน Supabase อีเมลอยู่ใน `auth.users` เท่านั้น เกมไม่เก็บอีเมลลงตารางของเกม (กติกาข้อมูลผู้เรียน) และยังไม่มีแนวคิด "ผู้ดูแล" ในเกมเลย
- ความคืบหน้า เครดิต และการปลดล็อกคำนวณจากบันทึกการเล่นในเครื่อง (`SaveData`) ทุกคนใช้กฎเดียวกัน
- ผู้เล่นที่ใช้ Google โดยไม่มีรหัสห้องอยู่ในห้อง `SOLO` จึงไม่ขึ้นในแดชบอร์ดของห้องเรียนใด

## หลักการ

1. **สิทธิ์ผู้ดูแลตัดสินที่ฐานข้อมูลเท่านั้น** ไม่เชื่อค่าจากเบราว์เซอร์ และไม่ฝังอีเมลไว้ในโค้ดเกม (โค้ดเกมเปิดให้ทุกคนอ่านได้)
2. **เก็บเป็นรหัสบัญชี ไม่เก็บอีเมล:** ตารางใหม่ `admins` เก็บแค่ `user_id` (รหัสบัญชีใน `auth.users`) ไม่มีใครอ่านตารางนี้ได้จากเกม มีแค่ฟังก์ชัน `is_admin()` ที่ตอบว่า "บัญชีที่ล็อกอินอยู่เป็นผู้ดูแลหรือไม่" บัญชีไม่ระบุตัวตนได้คำตอบว่าไม่ใช่เสมอ
3. **ไม่สร้างผลการเรียนปลอม:** "จบเกม" ทำด้วยโหมดผู้ดูแลที่ปลดล็อกทุกอย่างตอนเล่น ไม่เขียนผลแบบทดสอบก่อน–หลังเรียน แกน AI หรือผลด่านต่อสู้ปลอมลงบันทึก ข้อมูลวัดผลจึงไม่ปนเปื้อน

## สิ่งที่จะทำ

### 1. ฐานข้อมูล (`supabase/schema.sql`)

- ตาราง `public.admins (user_id uuid primary key references auth.users on delete cascade)` เปิด RLS ไม่มีนโยบายให้อ่าน (ผู้เล่นอ่านไม่ได้)
- ฟังก์ชัน `public.is_admin()` (security definer) คืน true เฉพาะบัญชีที่อยู่ในตาราง
- แดชบอร์ดผู้สอน (`api/teacher.ts`) ไม่นับข้อมูลของบัญชีผู้ดูแล แม้ผู้ดูแลใส่รหัสห้องเรียนเพื่อลองเล่น
- ตั้งค่าบัญชีของคุณ: ใช้คีย์ของเซิร์ฟเวอร์ใน `.env` หารหัสบัญชีของอีเมลนี้แล้วเพิ่มลงตาราง (ต้องเข้าสู่ระบบด้วย Google ในเกมมาก่อนอย่างน้อยหนึ่งครั้ง บัญชีถึงจะมีอยู่) และรัน schema ใหม่บนฐานข้อมูลจริง

### 2. ในเกม: โหมดผู้ดูแล

หลังเข้าสู่ระบบด้วย Google เกมถาม `is_admin()` ถ้าใช่:

- **จบเกมแล้ว:** ทุกแมพเดินทางได้ ทุกห้องเปิด ทุกด่านต่อสู้เข้าได้ (ด่านที่ยังไม่ชนะเล่นได้ตามปกติ) ร้านเปิดขายของทุกแมพ ของทุกชิ้นรวมถึงรางวัลของเลเวลใช้ได้ เลเวลแสดงเป็นเลเวลสูงสุด
- **เครดิตไม่จำกัด:** HUD แสดง "∞" ซื้อได้ทุกชิ้นโดยไม่หักเครดิต ของใช้ไม่จำกัดจำนวนต่อแมพ
- มีป้าย "ผู้ดูแล" ที่ HUD และสวิตช์เปิด/ปิดโหมดผู้ดูแล (ปิดแล้วเล่นเหมือนนักเรียนได้ ใช้ลองเกมจริง)
- ค่า "เป็นผู้ดูแล" ไม่บันทึกลง `SaveData` ถามฐานข้อมูลใหม่ทุกครั้งที่เปิดเกม ออกจากระบบแล้วโหมดหายทันที

### 3. ตรวจบัญชีอื่น

- **เทสต์ฐานข้อมูล (PGlite):** บัญชีไม่ระบุตัวตน บัญชี Google อื่น และบัญชีที่ไม่อยู่ในตารางได้ `is_admin() = false` ผู้เล่นอ่านหรือเพิ่มแถวในตาราง `admins` เองไม่ได้
- **e2e แบบ Supabase จำลอง (`test:e2e:cloud`):** ล็อกอิน Google บัญชีอื่น ต้องเห็นเกมปกติ (เครดิตตามจริง แมพถัดไปยังล็อก) บัญชีผู้ดูแลเห็นโหมดผู้ดูแล e2e ปกติ (ไม่มีฐานข้อมูล) ต้องไม่เห็นโหมดผู้ดูแลเลย
- **ฐานข้อมูลจริง:** หลังตั้งค่า ตรวจว่าตาราง `admins` มีแค่ 1 แถว (บัญชีของคุณ) และนับจำนวนผู้เล่นทั้งหมดที่ข้อมูลอยู่ในสถานะชนะทุกด่าน (รายงานเป็นตัวเลขอย่างเดียว ไม่ดึงชื่อหรือข้อมูลรายคน) เพื่อยืนยันว่าไม่มีนักเรียนคนไหนได้สถานะจบเกมโดยไม่ได้เล่นเอง

### 4. เอกสาร

GDD ข้อใหม่ (บัญชีผู้ดูแล) คู่มือครู (วิธีเพิ่ม/ลบผู้ดูแล และบอกว่าข้อมูลของผู้ดูแลไม่ขึ้นแดชบอร์ด) README (คำสั่ง SQL ตั้งผู้ดูแล) และ CLAUDE.md

## ข้อจำกัดที่ควรรู้

- เกมเก็บความคืบหน้าในเครื่องของผู้เล่น คนที่แก้โค้ดในเบราว์เซอร์ของตัวเองได้ก็โกงเกมในเครื่องตัวเองได้อยู่แล้วทุกวันนี้ (เช่น แก้เครดิต) โหมดผู้ดูแลไม่ได้ทำให้เรื่องนี้แย่ลง และเพราะโหมดผู้ดูแลไม่เขียนผลการเรียนปลอม การโกงแบบนี้จึงไม่กระทบคะแนนก่อน–หลังเรียนในแดชบอร์ด
- การตั้งค่าบนฐานข้อมูลจริง (รัน schema และเพิ่มบัญชีผู้ดูแล) เป็นการแก้ระบบที่นักเรียนใช้อยู่ จะทำหลังเทสต์ผ่านครบ และทำเฉพาะส่วนที่เพิ่ม ไม่แตะข้อมูลของผู้เล่น

## คำถามที่ต้องยืนยัน

1. **"จบเกม" แบบไหน** แนะนำ: โหมดผู้ดูแลที่ปลดล็อกทุกอย่างโดยไม่เขียนผลการเรียนปลอม (ตามข้อ 2) อีกทาง: เขียนบันทึกให้เป็นผู้เล่นที่จบเกมจริง (ชนะทุกด่าน ได้แกนครบ มีผลแบบทดสอบหลังเรียน) ซึ่งเป็นข้อมูลปลอมและถ้าใส่รหัสห้องเรียนจะไปขึ้นแดชบอร์ด
2. **ให้ผมตั้งค่าฐานข้อมูลจริงเองไหม** แนะนำ: ให้ผมทำผ่านคีย์ใน `.env` หลังเทสต์ผ่าน (คุณต้องล็อกอิน Google ในเกมจริงก่อน 1 ครั้งถ้ายังไม่เคย) อีกทาง: ผมเตรียมคำสั่ง SQL ให้คุณวางใน Supabase SQL Editor เอง
3. **เพิ่มผู้ดูแลคนอื่นได้ไหมในอนาคต** แนะนำ: ได้ด้วยคำสั่ง SQL บรรทัดเดียวในคู่มือครู (ไม่มีหน้าจอจัดการในเกม เพื่อไม่ให้มีช่องทางให้ใครตั้งตัวเองเป็นผู้ดูแล)
