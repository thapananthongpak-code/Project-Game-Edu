# แผนรอบ 21: เอารหัสห้องเรียนออก และตรวจทั้งระบบก่อนใช้จริง

สถานะ: **ทำแล้ว** (ผู้ใช้เห็นด้วยตามที่แนะนำทั้ง 3 ข้อ ผลการตรวจอยู่ที่ GDD ข้อ 34–35) (เขียนเมื่อ 31 ต.ค. 2569 จากโค้ดที่ commit `31d0505`)

## สิ่งที่ผู้ใช้ขอ

1. เอาระบบใส่รหัสห้องเรียนออก
2. ตรวจทั้งระบบ หาจุดที่มีบั๊กก่อนนำไปใช้จริง

## สภาพตอนนี้ (ตรวจโค้ดและฐานข้อมูลแล้ว)

- หน้าลงทะเบียนมีช่อง "รหัสห้องเรียนจากครู" (ไม่บังคับ) สมุดเควสแสดงและแก้รหัสได้ บันทึกอยู่ใน `SaveData.profile.classCode`
- **รหัสห้องเรียนเป็นตัวตัดสินว่าข้อมูลขึ้นฐานข้อมูลกลางหรือไม่** (`sharable` ใน `progressStore.ts`): ใส่รหัส = ซิงก์ขึ้น Supabase ครูเห็นในแดชบอร์ด ไม่ใส่ = เก็บในเครื่องอย่างเดียว (ยกเว้นเข้าสู่ระบบด้วย Google ซึ่งเก็บใต้ห้อง `SOLO`)
- แดชบอร์ดผู้สอน (`/teacher`) เลือกดูทีละห้องด้วยรหัส และ "ลบข้อมูลของห้อง" ต้องพิมพ์รหัสยืนยัน
- ฐานข้อมูลจริงตอนนี้มีผู้เล่น 4 แถว รหัสห้อง `A`, `PVC1-67`, `SOLO` 2 แถว (หนึ่งในนั้นคือบัญชีผู้ดูแล)

ถ้าเอาช่องรหัสออกเฉย ๆ ผู้เรียนจะไม่มีทางส่งข้อมูลให้ครูเลย (ยกเว้นคนที่ใช้ Google) แดชบอร์ดจะว่าง จึงต้องเลือกว่าข้อมูลจะไปถึงครูอย่างไร (คำถามข้อ 1)

## สิ่งที่จะทำ

### 1. เอารหัสห้องเรียนออก (ตามที่แนะนำในคำถามข้อ 1–2)

- ลบช่องรหัสห้องเรียนในหน้าลงทะเบียนและสมุดเควส ข้อความที่พูดถึงรหัส และการตรวจรูปแบบรหัส
- ผู้เรียนทุกคนซิงก์ขึ้นฐานข้อมูลกลางอัตโนมัติ (ล็อกอินแบบไม่ระบุตัวตนอยู่แล้ว) เก็บใต้กลุ่มเดียว ข้อมูลที่ส่งเหมือนเดิม: ชื่อที่แสดง (ชื่อเล่นหรือเลขที่) กับความคืบหน้า ไม่มีอีเมลหรือชื่อจริง ภาพหลักฐานยังไม่ออกจากเครื่อง
- ฐานข้อมูล: คอลัมน์ `class_code` ยังอยู่ (ไม่ลบข้อมูลเดิม) ผู้เล่นใหม่ได้ค่าเดียวกันหมด `save_progress` ไม่บังคับรหัสจากเกมแล้ว บัญชีผู้ดูแลยังอยู่ใต้ `SOLO` และไม่ขึ้นแดชบอร์ด
- แดชบอร์ดผู้สอน: เข้าด้วยรหัสผ่านแล้วเห็นผู้เรียนทุกคนทันที ไม่ต้องเลือกห้อง ลบข้อมูลเปลี่ยนจาก "ลบทั้งห้อง" เป็นเลือกลบรายคน (ยืนยันก่อนลบ) CSV ไม่มีคอลัมน์รหัสห้อง
- บันทึกรุ่นเดิมที่มี `classCode` อ่านได้ปกติ ค่าเดิมถูกเพิกเฉย
- แก้คู่มือครู README CLAUDE.md (กติกาข้อมูลผู้เรียน) GDD และ schema test / e2e-cloud

### 2. ตรวจทั้งระบบก่อนใช้จริง

- **รันทุกชุดทดสอบ:** unit ทั้งหมด, e2e ทุกชุด (main struggle normal lab guide gear level auto energy hard keyboard touch), `test:e2e:cloud` (Supabase จำลอง: ลงทะเบียน เล่นต่อเครื่องอื่น เครื่องใช้ร่วมกัน เครือข่ายล่ม Google), `test:perf` (เวลาโหลดและเฟรมเรตเมื่อถ่วง CPU/เครือข่าย), `validate/verify:content`, `check:coverage`, `balance`, build
- **ตรวจโค้ดจุดเสี่ยง** (อ่านโค้ดหาบั๊ก): การบันทึกและย้ายข้อมูลรุ่นเก่า การซิงก์และเครือข่ายล่ม เครดิตติดลบหรือซื้อของซ้ำ ด่านต่อสู้ (พลังงาน ของใช้ กลายร่าง) การปลดล็อกห้องและแมพ ผู้เล่นติดถาวร หน้าต่างที่ปิดไม่ได้หรือคีย์บอร์ดค้าง แดชบอร์ดและ API (สิทธิ์ รหัสผ่าน ข้อมูลรั่ว)
- **ตรวจเว็บจริงที่ deploy อยู่:** เปิดหน้าเกมและ `/teacher` บน Vercel ดูว่าโหลดได้ ไม่มี error ใน console และ `/api/tutor` `/api/teacher` ตอบได้ (ไม่เขียนข้อมูลลงฐานข้อมูลจริง)
- **ผลลัพธ์:** รายงานบั๊กที่เจอแยกตามความรุนแรง แก้ทุกตัวที่เป็นบั๊กชัดเจนพร้อมเทสต์กันซ้ำ ข้อที่เป็นการเปลี่ยนพฤติกรรมของเกมจะถามก่อน

## คำถามที่ต้องยืนยัน

1. **ข้อมูลของผู้เรียนไปถึงครูอย่างไรเมื่อไม่มีรหัสห้อง** แนะนำ: ทุกคนซิงก์ขึ้นฐานข้อมูลกลางอัตโนมัติ ครูเห็นทุกคนในแดชบอร์ดเดียว (ข้อมูลที่ส่งมีแค่ชื่อเล่นหรือเลขที่กับความคืบหน้า แต่จากเดิมที่ส่งเฉพาะคนที่ใส่รหัส กลายเป็นส่งทุกคน) อีกทาง: ไม่ส่งอะไรเลย เก็บในเครื่องอย่างเดียว (แดชบอร์ดจะไม่มีข้อมูล ยกเว้นคนที่เข้าสู่ระบบด้วย Google)
2. **ข้อมูลเดิมในฐานข้อมูล (ห้อง A และ PVC1-67)** แนะนำ: เก็บไว้ แสดงรวมกับคนอื่นในแดชบอร์ด อีกทาง: ลบข้อมูลทดสอบเดิมทิ้งก่อนใช้จริง (ลบแล้วกู้ไม่ได้)
3. **ครูสอนหลายห้องไหม** แนะนำ: แดชบอร์ดเดียวรวมทุกคน (ครูแยกห้องจากชื่อที่แสดง เช่น ให้นักเรียนตั้งชื่อเป็น "ปวช1-12") อีกทาง: ครูกรองรายชื่อด้วยคำค้นในแดชบอร์ด (เพิ่มช่องค้นหา)
